## 1. 参与引擎与统一口径

| 引擎 | 角色 | 撮合精度 |
| --- | --- | --- |
| `reference` | **语义真值**（oracle，非业务引擎） | 按统一口径直接模拟 |
| `backtrader` | 高保真执行 | 逐笔订单 |
| `bt` | 组合层 | 按再平衡日权重 |
| `vectorbt` | 粗筛 | **不参与对拍**（不建模撮合细节，仅经桥调用） |

**统一成交口径（正文 §P4.5）**：

> 信号在 **T 日收盘**生成 → **T+1 开盘价**成交；T+1 不可交易则顺延到下一个可交易会话。

### ⚠️ 手册内部冲突（已按规程处置）

| 出处 | 成交口径 |
| --- | --- |
| 附录 **F.4.4 / F.8** | 信号后第一个有效交易日的 **收盘** 成交 |
| 正文 **§P4.5** | T 日收盘出信号 → **T+1 开盘** 成交 |

手册规定「凡与正文冲突处，以正文为准」，故**取 §P4.5 的 T+1 开盘**。
该冲突在此显式记录。

## 3. 差异分类（§P4.5 明确要求：区分「引擎设计不同」与「缺陷」）

### 3.1 属**引擎设计不同**（非缺陷）

| # | 差异 | 数值影响 | **判定依据（可复现）** |
| --- | --- | --- | --- |
| D1 | **bt 在再平衡日收盘撮合**，而统一口径是 T+1 **开盘** | 场景 A 上 7.05e-03 | 把参考内核也切到 `fill_at='close'`，偏差**降到 0（逐位一致）**。差异**完全由成交时点解释** —— 见 `test_bt_deviation_is_due_to_fill_timing_not_to_a_defect` |
| D4 | **bt 的向量化模型没有「交易日掩码」概念**，无法逐标的顺延停牌 | 多标的样本上 3.59e-02 | 见 §4.5：裁掉停牌会话后同一对引擎吻合到 **8.9e-16** —— 差异**全部**由停牌顺延解释 |
| D2 | **bt 不暴露逐笔成交** | 无数值影响 | bt 的 API 只给权重与净值；`trades` 为空表是**如实反映**，不是丢数据 |
| D3 | backtrader 原生佣金是 `size×price×c` | 已归零，无影响 | 见 §4「成本口径」 |

> **D1 的处置**：按 §P4.5「若某引擎无法表达该语义，**在对拍报告中记录**，而不是调其他引擎去迁就它」——
> 我们**没有**把 reference 改成收盘成交来让数字好看；reference 保持 T+1 开盘，
> bt 的差异照实记录，并用 `fill_at='close'` 的**诊断模式**证明归因正确。

### 3.2 属**缺陷**（已修复）

对拍过程中暴露并修复的缺陷 —— 均**不是**容差问题，而是真实错误：

| # | 缺陷 | 症状 | 修复 |
| --- | --- | --- | --- |
| F1 | 参考内核用**原始收盘价**估值 | 三市场联合索引里「只有别的市场开市」的日子收盘价为 `NaN` → 净值**静默变成 NaN** | 估值改用因果 `ffill` 的最近有效价（F.4 允许估值沿用）；成交仍用真实开盘价 |
| F2 | 挂单在**决策日**就按收盘价定份额 | 决策收盘 ≠ 次日开盘 → 现金用不尽、**成本约束被绕过**（开盘低于收盘时根本不触发）、`cash_limited` 永不记录 | 改为**成交时刻、按成交价、按当时权益**折算份额 |
| F3 | backtrader 与参考**两边各收一次成本** | 单标的满仓 10bps 时净值少 **999.0**（正好一次佣金） | 成本只由**份额折减**表达（F.6），cerebro 佣金置 0 |
| F4 | backtrader 的 `index` 误传 **bundle 索引**而非 **feed 主时间轴** | 下标与 `len(self)` 错位，且随「别的市场开市天数」漂移 → 成交推迟一日（成交价 101.57 → 102.75） | 传入各 feed 日期的**并集**作为主时间轴 |
| F5 | 权重列名与 universe **类型不一致**（`"1"` vs `1`） | `reindex` 全落空 → 所有目标静默变 0 → 策略**看起来什么都没买** | 加 **fail-closed** 检查：对不齐即报错 |
| F6 | **`envs/vbt` 无 parquet 引擎** | 桥递过去的输入 Parquet 读不了 → 跨环境数据交换**根本跑不通** | 改用该环境已有的 `duckdb` 读写 Parquet（不新增依赖） |
| F7 | spawn 演示指望 `multiprocessing` 自行拦截 | **实测会挂住**而非失败 → 用例超时、无法作为证据 | 改为**继承的深度计数**，失败确定且毫秒级 |
| F8 | **减仓到非零目标被静默忽略**（参考内核与 backtrader **同源**） | 参考内核只在目标权重 = 0 时才卖 → 「1.0 减到 0.25」完全不动；backtrader 用 `min(-delta, current)` → 把仓位**清成 0** | 参考内核改为按目标份额卖出（含减仓）；backtrader 改为 `sell(size=-delta)` |

> F8 的性质最值得警惕：**参考内核是语义真值，它错了，整个对拍就没有基准**。
> 而且这类缺陷只在「部分减仓」时才现形 —— 只测 buy&hold 与清仓永远看不到。

## 4. 成本口径（一次说清，避免重复计息）

F.6 的复利式口径：`(1 + r_net) = (1 − c) × (1 + r_gross)`

* 买入可得份额 = `现金 × (1 − c) / 价格` —— **减法**还原，不是除法；
* 因此成本**已经**体现为「少买的份额」，**不得**再另行扣一次佣金；
* backtrader 原生 `setcommission(percabs=True)` 是**在成交额外另收** `size×price×c`，
  叠加即重复计成本（实测差 999.0）。故本项目将 cerebro 佣金置 0，
  并在 `notify_order` 中反推 `gross×c/(1−c)` 记账，使日志口径与参考内核一致。

**换汇成本**独立配置（F.8）。三个 runner 当前**均不建模换汇**：
`fx_cost_bps ≠ 0` 时**直接报错**，而不是当 0 悄悄放过
（`test_fx_cost_is_refused_rather_than_silently_ignored`）。

## 4.5 多标的换仓（**不在原 §P4.5 的 A/B/C 场景内**）

在 P3→P4 贯通冒烟时用一个**真实策略**（3 标的 SMA 择时 + 周频等权调仓）发现缺口。
**P5 已把两个缺口全部定位**（结论：都不是撮合算错）：

| 引擎 | 原表现 | **P5 定位结论** |
| --- | --- | --- |
| `backtrader` | **505 笔买单被判 `Margin` 并整单拒绝**（净值偏 16%），**完全静默** | 表达能力缺口：同根 bar「卖 A 买 B」时，下单校验用**本根收盘价+当前现金**，同根卖出所得尚未入账 → 拒单。F.5 要的是**缩减订单**。**处置：fail-closed**（非零未成交即抛错，见下）。 |
| `bt` | 能跑完，但 vs 参考口径偏 **4.61e-02**；对齐成交时点后仍 **3.56e-02** | **停牌顺延缺口**（见下）—— 已定位并**显式标注**；撮合本身正确。 |

### 4.5.1 backtrader：fail-closed（保持）

`BacktraderRunner` 统计未成交订单，**非零即抛 `EngineError`**，报错含日期、标的、
状态与替代路径；`stats` 带 `n_rejected` / `rejected_sample`。多标的换仓暂以
`reference` / `bt` 为准。用例：`tests/test_engine_parity.py::TestMultiAssetRebalanceGap`。

> ⚠️ 修复尝试记录（3 次均未成功，**已回退**）：自行推算可用现金 / `set_checksubmit(False)` /
> 改限价单 —— 均未清零，且会回归已通过的 A/B/C。按「不得为通过验证而放宽容差」回退。

#### P5.5 新发现的**另外两类** backtrader 拒单（broker 模型差异，**记录未修**）

用完整周频面板驱动 backtrader 时暴露（**不是** spec2weights 的问题）：

| # | 触发条件 | 机理 | 处置 |
| --- | --- | --- | --- |
| L1 | 面板**重复断言同一目标**（连续多行满仓 `1.0`） | `next_open()` 每行都重算 `desired = 权益×权重/开盘价`；价格下跌 → `desired > 持仓` → 补仓买单，而现金≈0 → **Margin**。参考内核按 F.5「缩减订单」（买入≈0）故不报错 | 对拍前压缩为**变化点**面板（语义等价，且正是决策 1 的「建仓/清仓」形态） |
| L2 | **跳空低开日建仓**（`0→1`） | backtrader **下单前保证金校验**用**上一收盘价**（券商当前标记价）而非成交开盘价；低开时 `size×昨收 > 现金` → **Margin 误拒**（实测 `pos=0`、`现金=净值`，**并非真缺钱**） | 未修：属 broker 模型差异。**对拍只取「一次建仓+一次清仓」受支持形态**（决策 1 = A） |

> L1/L2 是决策 1「缩小验证形态」的**实证理由** —— backtrader 的 broker 模型对
> 「重复目标」与「跳空建仓」这两类本平台常见形态并不忠实，不是数值容差问题。
> 用例见 `tests/test_p5_spec2weights.py`（docstring 有完整说明）。

### 4.5.2 bt：3.6% 缺口 = **停牌顺延**，已定位（P5，2026-09-29）

**机理**：bt 的 `WeighTarget` 只知道「日期 + 价格」，**没有交易日掩码**这一概念。
我们递进去的是 `ffill` 后的价格，于是当再平衡日落在**停牌/休市**会话上
（联合索引里常见：某市场休市而另一市场开市，例如 2020 长假期间 XSHG 休市而联合索引仍有会话），
bt 会**就地按停牌前的旧价成交**；而统一口径要求**顺延到下一个可交易会话**。
成交价不同 → 每个停牌缺口都漏一点进净值，10 年累积成 3.6%。
bt 的向量化模型**无法表达逐标的顺延**（一个日期一个权重向量），属**引擎表达能力**差异。

**归因证明（可复跑，`tests/test_p5_bt_halt.py`）**：

| 样本 | bt vs ref@open | bt vs ref@close | halt_sessions |
| --- | --- | --- | --- |
| 全样本（[1,2,3]，2598 会话） | 4.613e-02 | **3.591e-02** | **182** |
| 裁掉停牌会话（2416 会话） | 1.154e-02（纯成交时点） | **8.88e-16（机器精度）** | 0 |

> 裁掉停牌后二者吻合到**机器精度** → 偏差**全部**来自停牌顺延，**没有**隐藏的撮合缺陷。
> 这正是当初「先定位、再提交」要证伪的东西。

**同时修掉的两处「静默」问题**（都在 P5 定位过程中暴露）：

| # | 问题 | 修复 |
| --- | --- | --- |
| B1 | bt runner 用 bt 默认 `integer_positions=True`（份额**向下取整**），而统一口径用**分数份额** → 一处 ~3.3e-05、恰好卡在容差边缘的**静默**偏差 | bt runner 改 `integer_positions=False` |
| B2 | 参考内核的**收盘诊断模式**里，定份额用**开盘估值**、成交却用**收盘价**（自相矛盾）→ 给对拍注入 ~1.3e-3 伪偏差 | `MatchEngine.execute` 的定份额估值改为**跟随 `fill_at`** |

**处置（当前）**：bt **不**为迁就而改（§P4.5 明确规定「无法表达该语义时记录，而不是让别的引擎迁就」）。
改为**显式可见**：`BtRunner` 在 `stats["halt_sessions"]` 与
`run_meta["known_deviation"]`（`halt_deferral_unsupported`）中标注；>0 即表示本次结论
受停牌缺口影响、**不可**与统一口径直接对拍。真正的修复（给 bt 做逐标的顺延的下单层）
留待 P6 组合层一并处理。

## 6. 复现方式

```powershell
Set-Location 'D:\project\quant'
```
