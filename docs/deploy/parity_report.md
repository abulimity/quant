## 1. 参与引擎与统一口径

| 引擎 | 角色 | 撮合精度 |
| --- | --- | --- |
| `reference` | **语义真值**（oracle，非业务引擎） | 按统一口径直接模拟 |
| `backtrader` | 高保真执行 | 逐笔订单 |
| `bt` | 组合层 | 按再平衡日权重 |
| `vectorbt` | 粗筛 | **不参与对拍**（不建模撮合细节，仅经桥调用） |

**统一成交口径（正文 §P4.5）**：

> 信号在 **T 日收盘**生成 → **T+1 开盘价**成交；T+1 不可交易则顺延到下一个可交易会话。

### ⚠️ 手册内部冲突（已按规程处置）

| 出处 | 成交口径 |
| --- | --- |
| 附录 **F.4.4 / F.8** | 信号后第一个有效交易日的 **收盘** 成交 |
| 正文 **§P4.5** | T 日收盘出信号 → **T+1 开盘** 成交 |

手册规定「凡与正文冲突处，以正文为准」，故**取 §P4.5 的 T+1 开盘**。
该冲突在此显式记录。

## 3. 差异分类（§P4.5 明确要求：区分「引擎设计不同」与「缺陷」）

### 3.1 属**引擎设计不同**（非缺陷）

| # | 差异 | 数值影响 | **判定依据（可复现）** |
| --- | --- | --- | --- |
| D1 | **bt 在再平衡日收盘撮合**，而统一口径是 T+1 **开盘** | 场景 A 上 7.07e-03 | 把参考内核也切到 `fill_at='close'`，偏差**立刻降到 2.14e-05**（≤ 1e-4）。差异**完全由成交时点解释** —— 见 `test_bt_deviation_is_due_to_fill_timing_not_to_a_defect` |
| D2 | **bt 不暴露逐笔成交** | 无数值影响 | bt 的 API 只给权重与净值；`trades` 为空表是**如实反映**，不是丢数据 |
| D3 | backtrader 原生佣金是 `size×price×c` | 已归零，无影响 | 见 §4「成本口径」 |

> **D1 的处置**：按 §P4.5「若某引擎无法表达该语义，**在对拍报告中记录**，而不是调其他引擎去迁就它」——
> 我们**没有**把 reference 改成收盘成交来让数字好看；reference 保持 T+1 开盘，
> bt 的差异照实记录，并用 `fill_at='close'` 的**诊断模式**证明归因正确。

### 3.2 属**缺陷**（已修复）

对拍过程中暴露并修复的缺陷 —— 均**不是**容差问题，而是真实错误：

| # | 缺陷 | 症状 | 修复 |
| --- | --- | --- | --- |
| F1 | 参考内核用**原始收盘价**估值 | 三市场联合索引里「只有别的市场开市」的日子收盘价为 `NaN` → 净值**静默变成 NaN** | 估值改用因果 `ffill` 的最近有效价（F.4 允许估值沿用）；成交仍用真实开盘价 |
| F2 | 挂单在**决策日**就按收盘价定份额 | 决策收盘 ≠ 次日开盘 → 现金用不尽、**成本约束被绕过**（开盘低于收盘时根本不触发）、`cash_limited` 永不记录 | 改为**成交时刻、按成交价、按当时权益**折算份额 |
| F3 | backtrader 与参考**两边各收一次成本** | 单标的满仓 10bps 时净值少 **999.0**（正好一次佣金） | 成本只由**份额折减**表达（F.6），cerebro 佣金置 0 |
| F4 | backtrader 的 `index` 误传 **bundle 索引**而非 **feed 主时间轴** | 下标与 `len(self)` 错位，且随「别的市场开市天数」漂移 → 成交推迟一日（成交价 101.57 → 102.75） | 传入各 feed 日期的**并集**作为主时间轴 |
| F5 | 权重列名与 universe **类型不一致**（`"1"` vs `1`） | `reindex` 全落空 → 所有目标静默变 0 → 策略**看起来什么都没买** | 加 **fail-closed** 检查：对不齐即报错 |
| F6 | **`envs/vbt` 无 parquet 引擎** | 桥递过去的输入 Parquet 读不了 → 跨环境数据交换**根本跑不通** | 改用该环境已有的 `duckdb` 读写 Parquet（不新增依赖） |
| F7 | spawn 演示指望 `multiprocessing` 自行拦截 | **实测会挂住**而非失败 → 用例超时、无法作为证据 | 改为**继承的深度计数**，失败确定且毫秒级 |
| F8 | **减仓到非零目标被静默忽略**（参考内核与 backtrader **同源**） | 参考内核只在目标权重 = 0 时才卖 → 「1.0 减到 0.25」完全不动；backtrader 用 `min(-delta, current)` → 把仓位**清成 0** | 参考内核改为按目标份额卖出（含减仓）；backtrader 改为 `sell(size=-delta)` |

> F8 的性质最值得警惕：**参考内核是语义真值，它错了，整个对拍就没有基准**。
> 而且这类缺陷只在「部分减仓」时才现形 —— 只测 buy&hold 与清仓永远看不到。

## 4. 成本口径（一次说清，避免重复计息）

F.6 的复利式口径：`(1 + r_net) = (1 − c) × (1 + r_gross)`

* 买入可得份额 = `现金 × (1 − c) / 价格` —— **减法**还原，不是除法；
* 因此成本**已经**体现为「少买的份额」，**不得**再另行扣一次佣金；
* backtrader 原生 `setcommission(percabs=True)` 是**在成交额外另收** `size×price×c`，
  叠加即重复计成本（实测差 999.0）。故本项目将 cerebro 佣金置 0，
  并在 `notify_order` 中反推 `gross×c/(1−c)` 记账，使日志口径与参考内核一致。

**换汇成本**独立配置（F.8）。三个 runner 当前**均不建模换汇**：
`fx_cost_bps ≠ 0` 时**直接报错**，而不是当 0 悄悄放过
（`test_fx_cost_is_refused_rather_than_silently_ignored`）。

## 4.5 ⚠️ 已知缺口：多标的换仓（**不在原 §P4.5 的 A/B/C 场景内**）

在 P3→P4 贯通冒烟时用一个**真实策略**（3 标的 SMA 择时 + 周频等权调仓）发现缺口：

| 引擎 | 结果 |
| --- | --- |
| `reference` | 正常，净值 1,328,667 |
| `backtrader` | **505 笔买单被判 `Margin` 并整单拒绝** → 净值 **1,429,084**（偏差 **16%**）、且**完全静默** |

**机理**：backtrader 在「同一根 bar 内卖 A 买 B」时，下单校验用的是**本根收盘价**
与**当时现金**（`order.created.price` 实测 = `close[0]`），而同根卖出所得要到
本根结算后才入账 → 买单被拒。而 F.5 要求的是**缩减订单**，不是整单拒绝。

**为什么之前的 A/B/C 没抓到**：三个场景都是**单标的**的 buy&hold / 建仓 / 清仓，
**从未出现「卖一个买另一个」**。补上多标的换仓后才暴露。

### 处置（当前）：fail-closed，不给悄悄错掉的结论

- `BacktraderRunner` 现在会统计未成交订单，**非零即抛 `EngineError`**，
  报错含日期、标的、状态与替代路径；`stats` 里也带 `n_rejected` / `rejected_sample`。
- 多标的换仓**暂以 `reference` / `bt` 为准**。
- 用例：`tests/test_engine_parity.py::TestMultiAssetRebalanceGap`
  （断言「明确失败」而非「静默错误」）。

### ⚠️ 修复尝试记录（3 次均未成功，**已回退**）

| 尝试 | 结果 |
| --- | --- |
| 自行推算「现金 + 本根卖出所得」并等比缩减 | 505 → 145 笔，未清零 |
| `broker.set_checksubmit(False)` | 仍 140 笔（拒绝发生在结算阶段，非提交阶段） |
| 改市价单为**限价单**（`price=open`），使校验价与成交价一致 | 仍 140 笔 |

**并且这三次尝试会回归已经通过的 A/B/C**（场景 B 与 backtrader 成本单调性被打红）。
按 §0.1「不得为通过验证而放宽容差 / 伪造证据」，**已全部回退**，
保留「A/B/C 通过 + 多标的换仓明确失败」这一**诚实的**状态。
修复留待后续阶段（建议与 P6 组合层的换仓/现金约束一并处理）。
